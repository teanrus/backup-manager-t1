# Сборка и установка RPM-пакета

В этом каталоге находятся спецификация RPM-пакета, необходимые для него системные файлы и сценарий сборки. RPM устанавливает веб-интерфейс Backup Manager, Node.js API, конфигурацию Nginx и unit systemd.

> **Важно:** инструкция относится только к RPM-сборке. Debian-пакет собирается отдельно, с помощью сценариев в `deb-build/`. Текущая RPM-интеграция предназначена для Linux-систем с RPM, systemd и Nginx. Поддержка других дистрибутивов, включая Astra Linux, требует отдельной проверки и адаптации.

## Что устанавливает пакет

Пакет содержит:

- статические файлы веб-интерфейса React;
- локальный Node.js API, который хранит настройки, задания и журнал, проверяет SMB-подключение и выполняет задания;
- unit-файл `backup-manager-api.service`;
- конфигурацию Nginx для веб-интерфейса и проксирования запросов `/api/`;
- сценарии настройки и обслуживания.

Установочный пакет называется `redos-backup-manager`, а файлы программы размещаются в `/usr/share/redos-backup-manager`. Это исторические имена, сохранённые для совместимости. Имя пакета само по себе не означает, что сборка проверена на конкретном дистрибутиве.

Расписание обрабатывает backend. Отдельные старые systemd timer/cron-компоненты не используются для запуска новых заданий; сценарий первоначальной настройки отключает прежний timer и удаляет его cron-файл, если они остались от старой установки.

## Требования

### Для сборки

Собирать пакет нужно в Linux-среде с RPM-инструментами. Необходимы:

- Node.js 18 или новее;
- npm;
- `rpmbuild` (в RPM-дистрибутивах обычно входит в пакет `rpm-build`);
- `bash`, `make`, `cp`, `mkdir` и стандартные Unix-утилиты.

Сценарий `build-rpm.sh` подготавливает frontend и вызывает `rpmbuild`. Для установки типичных инструментов сборки на системе с DNF:

```bash
sudo dnf install nodejs npm rpm-build
```

Имена и доступность пакетов могут различаться в зависимости от дистрибутива и подключённых репозиториев. Зависимости самого проекта устанавливаются через npm из корня репозитория.

### Для установки и выполнения резервного копирования

RPM объявляет следующие системные зависимости:

- Nginx;
- Node.js 18 или новее;
- `rsync`;
- CIFS utilities (`cifs-utils`);
- Samba client (`samba-client`);
- OpenSSL;
- systemd.

Для работы также необходимы:

- работающий systemd;
- группа `nginx` — сценарий первичной настройки использует её для доступа Nginx к файлу авторизации;
- доступ к SMB/CIFS-серверу по сети;
- права, позволяющие backend монтировать CIFS-ресурс.

Backend установлен как системный сервис от `root`: монтирование SMB обычно требует системных привилегий. Учитывайте это при установке и настройке источников копирования.

## Сборка RPM

1. Получите исходный код проекта и перейдите в его корневой каталог — туда, где находятся `package.json` и `rpm-build/`.
2. При необходимости установите зависимости разработки и выполните проверки:

   ```bash
   npm ci
   npm run typecheck
   npm test
   ```

3. Запустите сценарий сборки:

   ```bash
   bash ./rpm-build/build-rpm.sh
   ```

Сценарий проверяет наличие `node`, `npm` и `rpmbuild`, устанавливает npm-зависимости, собирает frontend, подготавливает дерево `~/rpmbuild/` и запускает `rpmbuild`.

Готовый RPM ожидается по пути:

```text
~/rpmbuild/RPMS/noarch/redos-backup-manager-1.0.0-1.<суффикс>.noarch.rpm
```

Фактическое имя файла может включать дополнительный суффикс дистрибутива. Посмотреть созданные пакеты можно так:

```bash
find "$HOME/rpmbuild/RPMS" -type f -name '*.rpm' -print
```

### Через Makefile

Из корня проекта доступна цель:

```bash
make rpm
```

Она собирает frontend и запускает RPM-сборку через `rpmbuild`. Для подробной подготовки и диагностики используйте `rpm-build/build-rpm.sh`.

## Установка и первоначальная настройка

Установите собранный пакет с помощью пакетного менеджера целевого RPM-дистрибутива. Например, если пакет найден в `~/rpmbuild/RPMS/noarch/`:

```bash
sudo dnf install "$HOME"/rpmbuild/RPMS/noarch/redos-backup-manager-1.0.0-1*.rpm
```

Во время установки RPM пытается настроить systemd и запустить Nginx и API. Однако полноценный доступ к приложению появляется только после создания токена и файла авторизации — это делает следующий сценарий.

Выполните первоначальную настройку от `root`:

```bash
sudo /usr/share/redos-backup-manager/scripts/setup.sh
```

Сценарий:

1. создаёт каталог данных `/var/lib/backup-manager` с ограниченными правами;
2. создаёт `/etc/backup-manager`;
3. генерирует случайный секрет API и файл Basic Auth для Nginx;
4. включает и перезапускает `backup-manager-api.service` и Nginx;
5. выводит имя пользователя и сгенерированный пароль.

Сохраните показанный пароль в надёжном месте: сценарий выводит его в терминал, а приложение не показывает его повторно. Вход в веб-интерфейс:

- адрес: `http://localhost:8080`;
- имя пользователя: `backup`;
- пароль: значение, выведенное `setup.sh`.

Откройте адрес локально на том компьютере, где установлен сервис. Оба сервиса привязаны к loopback, поэтому интерфейс не предназначен для доступа с других компьютеров.

> **Повторный запуск `setup.sh` создаёт новые секреты.** Ранее выданный пароль перестанет подходить. После повторной настройки используйте новый пароль, напечатанный сценарием.

## Первый запуск и настройка резервного копирования

### 1. Настройте SMB/CIFS

Откройте раздел SMB в веб-интерфейсе и укажите:

- адрес или имя SMB-сервера;
- имя общей папки;
- имя пользователя;
- пароль, если сервер не использует гостевой доступ;
- домен или рабочую группу, если требуется;
- локальную точку монтирования, по умолчанию `/mnt/backup`.

Нажмите **«Сохранить»**, чтобы сохранить параметры, или **«Сохранить и проверить»**, чтобы сохранить их и проверить подключение. Сохранённый SMB-пароль хранится на диске backend и не возвращается в браузер. Если пароль уже задан, пустое поле при сохранении оставляет прежний пароль; для замены введите новое значение.

Проверка SMB использует `smbclient`. Фактическая проверка и монтирование доступны на Linux при наличии соответствующих утилит и сетевого доступа к серверу.

### 2. Создайте задание

В разделе заданий создайте резервную копию и задайте:

- название задания;
- существующий каталог-источник на компьютере с Backup Manager;
- расписание или запуск вручную;
- включено ли задание.

Backend запускает `rsync` и записывает результат в отдельный каталог задания внутри смонтированного SMB-ресурса. Задания выполняются последовательно.

### 3. Проверьте результат

Используйте ручной запуск для первой проверки. Просмотрите состояние задания и журнал в веб-интерфейсе. Убедитесь, что в целевой SMB-папке появился каталог задания и ожидаемые файлы.

Перед использованием в рабочей среде сначала проверьте процесс на тестовом источнике и тестовой SMB-папке. Резервное копирование не заменяет проверку восстановления данных.

## Обновление пакета

Соберите новую версию пакета и установите её поверх текущей средствами пакетного менеджера, например:

```bash
sudo dnf install ./redos-backup-manager-НОВАЯ_ВЕРСИЯ.rpm
```

Пакет RPM использует историческое имя `redos-backup-manager`. Настройки и задания backend хранятся отдельно от файлов приложения в `/var/lib/backup-manager`; обычное обновление пакета не предназначено для удаления этого каталога.

После обновления проверьте состояние сервисов и откройте интерфейс. Если изменились системные зависимости или конфигурация Nginx, проверьте сообщения systemd и Nginx до возобновления планового использования.

## Проверка и диагностика

### Состояние сервисов

```bash
sudo systemctl status backup-manager-api.service
sudo systemctl status nginx.service
```

Просмотр журналов:

```bash
sudo journalctl -u backup-manager-api.service -n 100 --no-pager
sudo journalctl -u nginx.service -n 100 --no-pager
```

Файл журнала событий заданий и ошибок Nginx:

```text
/var/log/redos-backup/nginx-error.log
/var/log/redos-backup/nginx-access.log
```

Журнал операций резервного копирования также доступен в веб-интерфейсе; его данные хранятся в файле состояния backend.

### Проверка конфигурации Nginx

```bash
sudo nginx -t
```

### Проверка локальной доступности

Проверьте, что Nginx слушает только loopback на порту `8080`, а API — на loopback на порту `3001`:

```bash
sudo ss -ltnp | grep -E '127\.0\.0\.1:(8080|3001)'
```

В браузере запрос к `http://localhost:8080` должен запросить имя пользователя и пароль. Неправильный пароль не должен открывать приложение.

### Частые проблемы

- **Сценарий настройки сообщает об отсутствии группы `nginx`.** В текущей RPM-интеграции Nginx должен использовать системную группу `nginx`. Проверьте состав пакета Nginx в установленном дистрибутиве; другая группа потребует адаптации сценария и прав на `/etc/backup-manager/htpasswd`.
- **API не запускается до настройки.** Это ожидаемо: systemd unit имеет `ConditionPathExists=/etc/backup-manager/api-token`. Выполните `setup.sh`, чтобы создать токен и включить сервис.
- **Nginx не запускается или не проходит проверку конфигурации.** Проверьте `nginx -t`, наличие файла `/etc/backup-manager/htpasswd`, владельца/группу и права чтения для Nginx.
- **Не проходит SMB-проверка.** Проверьте адрес сервера, имя ресурса, учётные данные, доступность сети и наличие `smbclient`.
- **Не выполняется копирование.** Проверьте, что backend работает на Linux, установлены `rsync` и `cifs-utils`, источник существует, а сервис имеет возможность смонтировать SMB. Подробная ошибка должна быть в журнале приложения и systemd.
- **Забыли пароль приложения.** Повторно запустите `setup.sh` от `root`. Он создаст новый пароль; прежний перестанет действовать.

## Удаление

### Удаление пакета с сохранением данных

Удалите RPM средствами пакетного менеджера:

```bash
sudo dnf remove redos-backup-manager
```

Удаление пакета удаляет принадлежащие ему файлы приложения и останавливает его API-службу. Отдельные системные данные и зависимости, установленные пакетным менеджером, могут сохраниться. Перед удалением проверьте, где хранятся конфигурация и резервные копии.

### Полное удаление установленных данных

В комплекте есть интерактивный сценарий полного удаления:

```bash
sudo /usr/share/redos-backup-manager/scripts/uninstall.sh
```

Он запрашивает подтверждение, останавливает API и системный сервис Nginx, затем удаляет каталог данных `/var/lib/backup-manager`, секреты `/etc/backup-manager`, файлы приложения, журналы и связанные legacy-конфигурации. Nginx может обслуживать и другие приложения: после выполнения сценария проверьте его конфигурацию и при необходимости запустите сервис повторно. Если SMB подключён через `/mnt/backup`, сценарий попытается размонтировать его. Резервные копии на SMB-сервере сценарий не удаляет.

> Не запускайте сценарий полного удаления, если хотите сохранить задания и настройки для последующей установки. Удаление `/var/lib/backup-manager` необратимо удаляет локальное состояние приложения.

## Пути и хранимые данные

| Назначение | Путь |
| --- | --- |
| Веб-интерфейс и backend | `/usr/share/redos-backup-manager/` |
| Сценарии приложения | `/usr/share/redos-backup-manager/scripts/` |
| Конфигурация Nginx | `/etc/nginx/conf.d/redos-backup-manager.conf` |
| API-токен и файл авторизации | `/etc/backup-manager/` |
| Состояние backend, задания, настройки SMB и журнал | `/var/lib/backup-manager/state.json` |
| Логи Nginx и legacy-журнал | `/var/log/redos-backup/` |
| Точка монтирования по умолчанию | `/mnt/backup` |
| systemd unit API | `/usr/lib/systemd/system/backup-manager-api.service` |

Путь состояния настраивается переменной `BACKUP_MANAGER_DATA_DIR` в окружении сервиса, но стандартная RPM-конфигурация использует `/var/lib/backup-manager`.

## Ограничения и безопасность

- RPM-сборка предназначена для локального интерфейса: Nginx и API слушают `127.0.0.1`. Не меняйте привязку на сетевой адрес и не публикуйте сервис через внешний reverse proxy без отдельной настройки TLS, аутентификации и модели доступа.
- API-сервис работает от `root`, поскольку монтирует CIFS-ресурс. Источник задания и точка монтирования должны быть выбраны аккуратно.
- Пароль SMB хранится в локальном JSON-файле состояния. Он не шифруется, но каталог backend создаётся с правами доступа только для владельца. Защитите систему, резервные копии локального состояния и доступ root.
- Секрет приложения создаётся при первоначальной настройке. Сохраните его вне терминального вывода; повторный запуск настройки сменит секрет.
- Удаление данных источника из резервной копии выключено по умолчанию. Если включить опцию удаления (`--delete`), файлы в целевом каталоге, отсутствующие в источнике, могут быть удалены. Внимательно проверяйте выбранные пути и сначала тестируйте настройку.
- Это средство копирования, а не система управления версиями резервных копий: отдельная неизменяемая история снимков и автоматическая проверка восстановления не заявлены.
- Уведомления по электронной почте и шифрование файла состояния не реализованы.
- Сборка RPM, пакетные install hooks и реальное монтирование SMB должны проверяться на целевой Linux-системе до эксплуатации.

## Состав каталога

- `build-rpm.sh` — сборка frontend и RPM-пакета.
- `SPECS/redos-backup-manager.spec` — метаданные пакета, его зависимости, состав и RPM install hooks.
- `SOURCES/backup-manager-api.service` — systemd unit локального API.
- `SOURCES/redos-backup-manager.conf` — конфигурация Nginx.
- `SOURCES/setup.sh` — создание секретов, прав доступа и запуск сервисов.
- `SOURCES/uninstall.sh` — интерактивное полное удаление.
