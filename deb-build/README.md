# Сборка и установка Debian-пакета

В этом каталоге находятся метаданные Debian-пакета, сценарии обслуживания, systemd unit, конфигурация Nginx и сценарий сборки `.deb` для Backup Manager.

Пакет предназначен для Debian и Ubuntu и производных систем, в которых доступны `dpkg`, systemd и Nginx. Сборка и установка на целевой системе требуют проверки: наличие совместимых имён групп, версий Node.js и системных пакетов зависит от дистрибутива.

> **Важно:** резервное копирование SMB/CIFS в текущей версии работает на Linux. Backend запускается от `root`, чтобы иметь возможность монтировать сетевые ресурсы. Установка пакета не заменяет проверку восстановления резервной копии.

## Состав пакета

Debian-пакет устанавливает:

- собранный React-интерфейс;
- Node.js API и планировщик заданий;
- systemd unit `backup-manager-api.service`;
- конфигурацию Nginx на `127.0.0.1:8080` с Basic-аутентификацией и проксированием `/api/`;
- сценарий первоначальной настройки;
- сценарии `postinst`, `prerm` и `postrm` для обслуживания пакета.

Имя пакета — `backup-manager`, архитектура — `all`. Версия пакета берётся из поля `version` в корневом `package.json`. Пакет не содержит Node.js runtime: он устанавливается как системная зависимость.

Данные приложений расположены вне каталога файлов пакета. При удалении пакета каталог `/var/lib/backup-manager` сохраняется, чтобы пользователь мог переустановить программу без потери конфигурации и заданий.

## Требования

### Для сборки

Собирать пакет следует в Linux-среде Debian/Ubuntu или совместимой системе. Необходимы:

- Node.js версии 18 или новее;
- npm;
- `dpkg-deb` (обычно предоставляется пакетом `dpkg`);
- Bash и стандартные Unix-утилиты.

Проверьте доступность инструментов:

```bash
node --version
npm --version
dpkg-deb --version
```

Установите Node.js и npm способом, подходящим для вашей версии дистрибутива. Если `dpkg-deb` не найден, установите пакет `dpkg`.

### Для установки и работы

Зависимости приложения указаны в `DEBIAN/control` и при установке разрешаются `apt`:

- `nginx`;
- `nodejs` версии 18 или новее;
- `rsync`;
- `cifs-utils`;
- `smbclient`;
- `openssl`;
- `systemd`.

Для первоначальной настройки также необходима системная группа `www-data`. Сценарий `setup.sh` использует её, чтобы предоставить Nginx доступ к файлу Basic Auth. Пакет рассчитан на систему с systemd и запускается с правами `root`.

## Сборка пакета

1. Получите исходный код проекта и перейдите в корневой каталог репозитория — туда, где находятся `package.json` и `deb-build/`.
2. Запустите сценарий:

   ```bash
   bash ./deb-build/build-deb.sh
   ```

   Либо используйте цель Makefile:

   ```bash
   make deb
   ```

Сценарий проверяет наличие `node`, `npm` и `dpkg-deb`, выполняет `npm ci`, собирает frontend командой `npm run build`, формирует временное дерево файлов пакета и запускает `dpkg-deb`. Временный каталог удаляется после сборки.

Готовый пакет появится здесь:

```text
dist/packages/backup-manager_<версия>_all.deb
```

Например, при версии `1.0.0`:

```text
dist/packages/backup-manager_1.0.0_all.deb
```

Версию задаёт поле `version` в корневом `package.json`; при её изменении сценарий подставляет значение в Debian-метаданные автоматически.

### Ручная сборка frontend

Обычно сценарий сам устанавливает npm-зависимости и создаёт frontend. Если требуется выполнить этапы вручную:

```bash
npm ci
npm run typecheck
npm test
npm run build
bash ./deb-build/build-deb.sh
```

Последняя команда повторно выполнит `npm ci` и `npm run build`, так как это часть сценария формирования `.deb`.

## Проверка собранного пакета

Просмотрите metadata:

```bash
dpkg-deb --info dist/packages/backup-manager_1.0.0_all.deb
```

Посмотрите список файлов:

```bash
dpkg-deb --contents dist/packages/backup-manager_1.0.0_all.deb
```

Вместо `1.0.0` укажите версию, которая находится в имени созданного файла. Перед распространением пакета проверьте его установку и удаление на чистой тестовой системе Debian/Ubuntu с systemd и Nginx.

## Установка и первоначальная настройка

Устанавливайте пакет на целевой Linux-компьютер с помощью `apt`. Из корня репозитория команда может выглядеть так:

```bash
sudo apt install ./dist/packages/backup-manager_1.0.0_all.deb
```

Если устанавливаете пакет из другого каталога, укажите фактический путь к `.deb`. `apt` установит заявленные системные зависимости.

Пакет устанавливает unit API и конфигурацию Nginx, но не создаёт секреты приложения автоматически. До создания API-токена backend unit не запускается: в нём задано условие `ConditionPathExists=/etc/backup-manager/api-token`.

После установки выполните сценарий настройки:

```bash
sudo /usr/share/backup-manager/scripts/setup.sh
```

Сценарий требует root и выполняет следующие действия:

1. проверяет наличие группы `www-data`;
2. создаёт `/etc/backup-manager` с ограниченным доступом;
3. создаёт каталог состояния `/var/lib/backup-manager`;
4. генерирует случайный API-токен и хеш пароля для Nginx;
5. выставляет права доступа на секреты;
6. проверяет конфигурацию Nginx командой `nginx -t`;
7. включает и перезапускает `backup-manager-api.service` и `nginx.service`;
8. выводит имя пользователя и пароль приложения.

Запишите пароль, показанный в терминале. Пароль пользователя `backup` не показывается интерфейсом повторно. Для входа откройте на самом компьютере, где установлен сервис:

```text
http://localhost:8080
```

Используйте имя пользователя `backup` и пароль, выведенный установочным сценарием.

> **Повторный запуск `setup.sh` создаёт новый пароль и токен.** Старый пароль перестанет работать. Используйте новый пароль, который сценарий выведет после настройки.

### Если `nginx -t` завершился ошибкой

Не перезапускайте Nginx, пока ошибка не исправлена: конфигурация пакета ссылается на `/etc/backup-manager/htpasswd`, который создаётся сценарием настройки. Проверьте вывод `nginx -t`, наличие и права файла авторизации, а также конфигурацию других сайтов. После исправления повторите настройку или перезапустите сервисы вручную.

## Первый запуск

### Настройка SMB/CIFS

В веб-интерфейсе перейдите к настройкам SMB и укажите сервер, имя общего ресурса, пользователя, домен или рабочую группу (если требуется) и точку монтирования. Значение по умолчанию — `/mnt/backup`.

Нажмите **«Сохранить»**, чтобы сохранить конфигурацию, или **«Сохранить и проверить»**, чтобы сохранить её и проверить доступ. Для проверки необходимы сетевой доступ и `smbclient`; для выполнения заданий также необходимы `rsync` и `cifs-utils`.

Пароль SMB хранится в локальном состоянии backend и не возвращается через API в браузер. Если пароль уже был сохранён, пустое поле пароля оставляет прежнее значение; для замены введите новый пароль.

### Создание и запуск задания

В разделе заданий создайте задачу, задайте название, существующий каталог-источник и нужное расписание. Для первичной проверки запустите задание вручную и проверьте его состояние и журнал в интерфейсе.

Backend монтирует SMB-ресурс и использует `rsync` для копирования в отдельный каталог задания внутри точки монтирования. Задания выполняются по очереди. Убедитесь, что выбранная SMB-папка содержит ожидаемую копию.

Перед регулярным запуском проверьте настройки на тестовом каталоге и тестовом SMB-ресурсе. Отдельно проверьте, что данные можно восстановить из созданной копии.

## Обновление

Соберите новый `.deb` и установите его поверх текущей версии:

```bash
sudo apt install ./dist/packages/backup-manager_НОВАЯ_ВЕРСИЯ_all.deb
```

При конфигурировании пакета `postinst` перечитывает systemd и, если уже создан API-токен, перезапускает API. Nginx перезагружается только при наличии файла авторизации и успешном `nginx -t`.

Настройки, задания и журнал остаются в `/var/lib/backup-manager`. Не удаляйте этот каталог при обновлении, если хотите сохранить состояние приложения.

## Проверка сервисов и диагностика

Проверьте статус API и Nginx:

```bash
sudo systemctl status backup-manager-api.service
sudo systemctl status nginx.service
```

Посмотрите журналы systemd:

```bash
sudo journalctl -u backup-manager-api.service -n 100 --no-pager
sudo journalctl -u nginx.service -n 100 --no-pager
```

Проверьте конфигурацию Nginx и локальные порты:

```bash
sudo nginx -t
sudo ss -ltnp | grep -E '127\.0\.0\.1:(8080|3001)'
```

Ожидается, что Nginx слушает `127.0.0.1:8080`, а API — `127.0.0.1:3001`. Журнал заданий отображается в интерфейсе и хранится backend в `/var/lib/backup-manager/state.json`. Диагностику выполнения SMB и `rsync` начинайте с сообщений в журнале приложения и `journalctl`.

### Частые проблемы

- **Нет группы `www-data`.** Сценарий настройки рассчитан на стандартную группу Nginx в Debian/Ubuntu. Проверьте группу пользователя Nginx в конкретном дистрибутиве; если она отличается, необходимо согласованно изменить права в `setup.sh`.
- **API не запускается сразу после установки.** Это штатное поведение до выполнения `setup.sh`: systemd ждёт появления `/etc/backup-manager/api-token`.
- **Ошибка `nginx -t` из-за отсутствующего файла пароля.** Выполните `setup.sh`, который создаёт `/etc/backup-manager/htpasswd`; если ошибка сохраняется, исправьте её согласно выводу проверки.
- **Не открывается интерфейс.** Убедитесь, что настройка завершилась успешно, сервисы запущены, адрес используется на локальном компьютере и порт `8080` не занят другой службой.
- **Не работает SMB-проверка или копирование.** Проверьте адрес сервера и имя ресурса, учётные данные и сетевой доступ, наличие `smbclient`, `cifs-utils`, `rsync`, а также ошибки API в `journalctl`.
- **Забыли пароль приложения.** Повторно выполните `setup.sh` от root и используйте новый пароль. Прежний пароль перестанет действовать.

## Удаление и сохранность данных

Удалить пакет, сохранив пользовательские настройки и данные:

```bash
sudo apt remove backup-manager
```

Сценарий `prerm` при удалении останавливает и отключает API-службу. Файл конфигурации Nginx зарегистрирован как conffile и при обычном `remove` может остаться. Каталог состояния `/var/lib/backup-manager` также сохраняется.

Полностью очистить пакет и его conffile:

```bash
sudo apt purge backup-manager
```

Сценарий `postrm` при `purge` удаляет файлы авторизации из `/etc/backup-manager`. Сам сценарий не удаляет `/var/lib/backup-manager` и не гарантирует удаление всех данных, созданных после установки. Если требуется удалить локальные настройки и задания, сначала остановите сервис, затем отдельно удалите каталог состояния:

```bash
sudo systemctl stop backup-manager-api.service
sudo rm -rf /var/lib/backup-manager
```

Эта команда необратимо удаляет локальные задания, настройки SMB и журнал. Она не удаляет резервные копии на SMB-сервере. Перед удалением убедитесь, что выбран именно каталог данных приложения.

## Пути и права доступа

| Назначение | Путь |
| --- | --- |
| Веб-интерфейс | `/usr/share/backup-manager/web/` |
| Backend API | `/usr/share/backup-manager/server/index.js` |
| Сценарий настройки | `/usr/share/backup-manager/scripts/setup.sh` |
| Конфигурация Nginx | `/etc/nginx/conf.d/backup-manager.conf` |
| API-токен и Basic Auth | `/etc/backup-manager/` |
| Настройки, задания, SMB-конфигурация и журнал | `/var/lib/backup-manager/state.json` |
| Логи Nginx | `/var/log/backup-manager/` |
| systemd unit | `/usr/lib/systemd/system/backup-manager-api.service` |
| Точка монтирования SMB по умолчанию | `/mnt/backup` |

После первичной настройки каталог состояния должен иметь права `0700`, API-токен — `0600`, а файл Nginx Basic Auth — `0640` с группой `www-data`. В файле состояния содержатся чувствительные данные, включая пароль SMB; не ослабляйте права на каталог и его содержимое.

## Ограничения и безопасность

- Nginx и API принимают подключения только на loopback. Интерфейс предназначен для локального использования, а не для публикации в сети или интернете.
- Вход защищён Basic Auth. Используйте его только через локальный интерфейс; не передавайте пароль по незашифрованному соединению через недоверенную сеть.
- API работает от root, так как выполняет монтирование CIFS. Сервис и доступ к его настройкам следует считать привилегированными.
- Пароль SMB хранится локально в файле состояния и не шифруется. Защищайте хост, доступ root и резервные копии `/var/lib/backup-manager`.
- Не запускайте dev-backend от root и не используйте его вместо установленного авторизованного сервиса.
- Опция `--delete` выключена по умолчанию. Если её включить, файлы в копии, отсутствующие в источнике, могут быть удалены.
- Пакет проверяет выполнение и ведёт журнал, но не реализует неизменяемые снимки, шифрование локального хранилища, email-уведомления или автоматизированную проверку восстановления.
- Пакет и его install scripts необходимо проверить на целевой версии Debian/Ubuntu, прежде чем использовать в рабочей среде.

## Файлы каталога

- `build-deb.sh` — устанавливает npm-зависимости, собирает frontend и формирует `.deb`.
- `DEBIAN/control` — имя пакета, версия-заглушка, архитектура и зависимости; версия заменяется из `package.json` при сборке.
- `DEBIAN/conffiles` — путь к конфигурации Nginx, сохраняемой при обычном удалении.
- `DEBIAN/postinst` — перечитывание systemd и перезапуск сервисов при обновлении уже настроенного приложения.
- `DEBIAN/prerm` — остановка и отключение API при удалении.
- `DEBIAN/postrm` — очистка файлов авторизации при `apt purge`.
- `setup.sh` — первоначальное создание секретов и запуск сервисов.
- `backup-manager-api.service` — systemd unit локального backend.
- `backup-manager.conf` — Nginx virtual host, ограниченный loopback.
